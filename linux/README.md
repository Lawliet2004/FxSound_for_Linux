# FxSound on Linux (PipeWire)

Linux port of FxSound. The Windows build (Visual Studio solutions under
`fxsound/Project`) is unchanged; this tree adds a CMake build that targets
Linux + PipeWire.

## Status

The app builds, installs, and runs on PipeWire-based distros (Arch, Fedora
34+, Ubuntu 22.04+, etc.).

Global shortcuts use XCB on X11 and the xdg-desktop-portal `GlobalShortcuts`
interface on Wayland (including sessions with XWayland). Your compositor must
provide this portal. Enabling or changing shortcuts may open its permission
and configuration dialog; the compositor chooses the final binding. Denied
requests are logged and do not repeatedly reopen the dialog. Disable/re-enable
shortcuts to retry. Portal service restarts trigger a fresh session. The GUI
remains responsive while consent is pending. Native compositor interaction
still needs a manual Plasma Wayland acceptance check.

## Install

### AppImage (recommended — no install needed)

```sh
# Build locally:
./packaging/build-appimage.sh
./FxSound-1.2.8.0-x86_64.AppImage

# Or grab the AppImage from the GitHub Actions artifacts / release page.
```

### System install

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX=/usr
cmake --build build
sudo cmake --install build
```

### Arch / CachyOS (AUR)

```sh
cd packaging
makepkg -si
```

## Build from source

```sh
# One-time: fetch JUCE 6.1.6 and the Resources submodule
git submodule update --init --recursive --depth 1

cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/FxSound
```

### Dependencies (Arch / CachyOS)

```sh
sudo pacman -S --needed base-devel cmake ninja \
  libx11 libxext libxinerama libxrandr libxcursor \
  freetype2 fontconfig mesa alsa-lib \
  xcb-util-keysyms libxcb \
  glib2 pipewire
```

```sh
sudo apt-get install -y \
  cmake ninja-build \
  libx11-dev libxext-dev libxinerama-dev libxrandr-dev libxcursor-dev \
  libfreetype6-dev libfontconfig1-dev libgl1-mesa-dev libasound2-dev \

```

## CI

GitHub Actions builds an AppImage and runs the `unit` tests on every push and
pull request to `main` and `develop/linux`, using an `ubuntu-22.04` runner
(glibc 2.35 baseline). The workflow is at
`.github/workflows/build-appimage.yml`. Artifacts are uploaded for 30 days;
tagged releases (`v*.*.*.*`) produce a draft GitHub Release automatically.

## Layout of the Linux port

**Build system**
- `CMakeLists.txt` — root Linux CMake build. Replicates the Projucer export
  and links DfxDsp + AudioPassthru.
- `dsp/DfxDsp.cmake` — builds the real DSP + shared util sources.
- `audiopassthru/AudioPassthruLinux.cmake` — builds the PipeWire backend.
- `packaging/fxsound.desktop` — freedesktop desktop entry.
- `packaging/PKGBUILD` — AUR package recipe.
- `packaging/build-appimage.sh` — AppImage builder (downloads linuxdeploy +
  appimagetool automatically).
- `.github/workflows/build-appimage.yml` — CI workflow.

**Linux support layer**
- `linux/win_compat.h` — minimal Win32 *type* aliases so Windows-typed GUI
  declarations parse on Linux. Types only; no faked Win32 functions.
- `linux/SysInfo_linux.cpp` — Linux `SysInfo` (the Windows version is COM-based).
- `linux/LinuxHotkeys.cpp/.h` — X11 global shortcuts; `PortalHotkeys.cpp/.h` implements Wayland portal sessions.
- `linux/stubs/` — stub `AudioPassthru` and `DfxDsp` used when the real
  backends are disabled via CMake options (see below).

**Tray icon**
- `linux/tray/fx_tray_sni.h` / `fx_tray_sni.cpp` — `org.kde.StatusNotifierItem`
  + `com.canonical.dbusmenu` over GDBus. Runs its own GLib main loop on a
  background thread. Left-click toggles the main window; the dbusmenu serves
  the full context menu to Wayland panels (Waybar, KDE Plasma) natively —
  no JUCE popup required. Menu refreshes automatically on model state changes.

**DSP Linux support layer** (`dsp/linux/`)
- `windows.h`, `conio.h`, `dos.h`, `direct.h`, `io.h`, `share.h`, `shlobj.h`,
  `Shlwapi.h`, `winbase.h`, `mmsystem.h` — stand-ins for Windows SDK headers.
- `<build>/lc_headers/` — symlinks bridging the DSP's inconsistent include
  casing to the real (case-sensitive) header files. Generated by
  `dsp/DfxDsp.cmake` at configure time; nothing to set up by hand.
- `reg_linux.cpp` — in-process key/value store replacing the Windows registry.
- `slout_linux.cpp`, `file_linux.cpp`, `pwav_convert_linux.cpp` — Linux
  implementations of the logger, file helpers, and sample converters.
- `test_dsp.cpp` — the `dsp_selftest` binary.

Windows-only code paths in shared GUI sources are guarded with `#ifdef _WIN32`.

## CMake options

| Option | Default | Purpose |
|--------|---------|---------|
| `FXSOUND_STUB_DSP` | `OFF` | Use stub DfxDsp instead of the ported engine |
| `FXSOUND_STUB_AUDIO` | `OFF` | Use stub AudioPassthru instead of PipeWire |


### Current port verification and packaging

See [`docs/development/KUBUNTU_PORT.md`](../docs/development/KUBUNTU_PORT.md) for
current evidence and remaining acceptance gates. Historical PR claims do not
replace tests against the current worktree. Windows visual/DSP parity remains
unverified by user agreement.

The login checkbox uses a stable AppImage path and Desktop Entry quoting.
`--autostart` starts in the tray. After moving an AppImage, re-enable the setting
from its new location. `packaging/install.sh [--yes] package.deb` installs through
apt; `packaging/uninstall.sh [--yes]` removes it and the invoking user's matching
native login entry while preserving presets/AppImage entries. Cleanup needs
Python 3. Do not run these scripts inside a directory being deleted by removal.

Additional private tests (never use a host audio session):

```sh
linux/tests/run-isolated.sh ctest --test-dir build -L pw-live --output-on-failure
ctest --test-dir build -L appimage-login --output-on-failure
# Override FXSOUND_FIREFOX / FXSOUND_CHROMIUM for native browser binaries.
ctest --test-dir build -L desktop-clients --output-on-failure
```

The browser fixture requires Firefox, Chromium, Chrome and ffplay plus Xvfb,
X11 utilities, PipeWire tools and GDBus. It uses temporary profiles and a local
HTTP WAV fixture; Chromium-family automation disables its sandbox for that
trusted local fixture. It never loads user browser profiles.

A disposable package check can be reproduced with Docker:

```sh
docker build -f linux/tests/package-test.Dockerfile -t fxsound-package-test linux/tests
docker run --rm --mount "type=bind,source=$PWD,target=/work,readonly"   fxsound-package-test bash /work/linux/tests/test_package_container.sh
```

The container has no host audio/device or configuration mounts. It runs apt
installation, actual private-server playback tests and native uninstall cleanup.

Linux login can precede PipeWire/WirePlumber startup. FxSound stays alive and
retries the transport every two seconds while preserving saved power/bypass and
DSP settings. The `pw-restart` CTest label covers delayed startup in both power
states as well as server/session-manager recovery in private sessions.
